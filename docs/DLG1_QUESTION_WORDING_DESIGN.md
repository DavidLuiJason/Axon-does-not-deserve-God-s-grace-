## 1. What was measured first (2026-11-06, main zip, Director sandbox)
- J2 (`decisionRecord.ts`) accepts a question only if, after trimming, it has 1 to 200 characters and at most ONE `?`; kinds CLARIFICATION, MISSING-INPUT, APPROVAL; permission ASK needs an APPROVAL question and only then; NEVER carries no question; a `confidence` key is refused.
- J6 (`actOrAsk.ts`) returns `outcome` ACT / ASK / BLOCK, `askKind` (null or the three kinds), `sayReading` (true only when it ACTs on one of two close readings) and reason codes. Reason codes seen in the code: `no-reading`, `two-readings`, `not-undoable`, `missing-input`, `permission-never`, `two-readings-undoable`, `readings-same-result`, `default-used`, `context-answers`, `safe-step-answers`, `one-reading`.
- The real schemas (`actionSchemas.ts` DATA table): 63 tools, 123 slots, 70 of them required, 33 tools have at least one required slot, 86 distinct slot ids, 40 distinct REQUIRED slot ids. Slot kinds: text 36, choice 31, yes-no 20, number 19, file 11, duration 2, time 2, date 2.
- The 40 required slot ids: algorithm, angle, archive, bill, count, date, durationMs, expression, file, fileA, fileB, files, format, from, input, items, language, length, level, meaning, mode, name, number, operation, options, original, pattern, people, revised, sentences, term, text, tipPercent, to, toFormat, value, values, video, word, yearlyRate.
- Tool display names exist (`toolCatalog.ts`, a `name` per tool, already on screens). Slot display names do NOT exist anywhere. Several ids are code names (`durationMs`, `fileA`, `toFormat`, `tipPercent`, `yearlyRate`); some are ambiguous alone (`to`, `from`, `mode`, `input`, `value`).
- No real tool sends or spends and none is irreversible (CHR1 and FEED2 measurements), so APPROVAL questions are driven today by `owner-approval` preconditions and by the Charter's `ask` list; the sends, spends and deletes frames are exercised by fixtures until a tool needs them.
- NOT MEASURED: the longest real tool name and whether four names plus a frame fit 200 characters (the DLG2 sweep decides, L8); whether the `src/brain/mind` guards (no regex literals, no arrays of 3 or more string literals) reach `src/decision` (the DLG2 card checks first).

## 2. Decisions (L1 to L9)
- **L1 ONE PURE ENGINE AFTER J6 (placement).** `makeQuestion` in `src/decision/questionWording.ts`, next to J2, J6 and the feed. It receives J6's result plus typed FACTS and returns plain text only. It never sees the message text, never reads `confidence`, never sets route, depth or permission, and has no Date, random or IO. The order stays D1/D4: Resolution, feed, J6, THEN wording, THEN J2 records (J2 needs the text). Dialogue state keeps the pending question (`setPending` takes the text); the engine does not touch it. The feed table lists DLG1 as depending on FEED3: that is the wrong way round. The engine needs only J6 and the feed's facts; FEED3 (wiring) needs DLG2. Corrected here.
- **L2 TYPED FACTS (the only input).** `{ kind, readings, slots, effects, undoable, action, variant, language }`. `readings`: 0 to 4 tool display names. `slots`: 1 to 4 plain labels of the missing slots (L3). `effects`: the effect classes in owner words (sends, deletes, spends, changes a setting, writes a file, stores a note, uses the network, uses the microphone). `undoable`: yes or no, from J6's input. `action`: the tool display name plus at most 3 values the owner already gave, each clipped to 40 characters, inserted VERBATIM and never reworded (data, not structure: no value can change a frame). `variant`: a whole number from Dialogue's turn count (L4). `language`: `en` (roadmap 6: a second language comes later through the same pieces file).
- **L3 PLAIN LABELS: NO CODE NAME EVER REACHES THE OWNER (owner design fix 2).** Slot labels come from a SLOT LABEL TABLE keyed by `tool.slot` (a bare slot id is ambiguous), data only, owner-approved wording, one plain phrase each ("the text", "the file to convert", "the format to convert to"). MEASURED need: 70 required pairs (33 tools). A pair with no label falls back to its slot KIND word ("the text", "the choice", "yes or no", "the number", "the file", "the length of time", "the time", "the date") joined to the tool name, so there is no hole and no code name even before the table is complete (FL15 loud: the engine reports `label-fallback` in its reason codes). The table is made by job SLB1 and later by each wiring card (optional `slotLabels`, add-only like the other generated parts, hand wins).
- **L4 COMPOSED FROM A CLOSED SET OF PIECES, NEVER ONE SENTENCE PER SCENARIO (FL13, 7D FLEXIBLE SPEECH).** A question is a lead-in piece (may be empty) plus a body frame for its kind plus the inserted facts. The pieces live in ONE closed-set file `src/decision/questionPieces.ts` (one named file per group, FL13), about 15 pieces in all (estimate: 4 lead-ins, 3 frames each for CLARIFICATION, MISSING-INPUT and APPROVAL, 2 for NO-READING), approved by the owner as a SET before the card runs. `variant` picks among them deterministically (turn count modulo the number of pieces), so the same facts and the same variant give the same text (testable) and consecutive questions do not repeat one wording. Free personal phrasing WORKS ONLY IF the optional model tier exists (FL13 honest limit).
- **L5 PROPERTIES THAT THE TEST CHECKS (not sentences).** P1 exactly one question: one `?` and J2 accepts it. P2 1 to 200 characters after trimming. P3 CLARIFICATION names EVERY reading by tool name, in the order given, and NO-READING names none and asks for a rephrase or a tool choice. P4 MISSING-INPUT names EVERY missing slot by its plain label and says which tool needs it. P5 APPROVAL names the effect classes it was given and exactly what would be done (the action field), and says plainly when it cannot be undone. P6 no code name: no output contains a slot id, a tool id with a hyphen, a camelCase word, or a reason code. P7 never asks what context answers (the engine is only called for slots J6 marked OWNER-ONLY; a slot in `contextFills` or `safeStepFills` is refused: `slot-answerable`). P8 same input, same output; different `variant` gives a different text for every kind that has two or more frames. P9 every inserted value appears verbatim and clipped values end with an ellipsis mark, never mid-word without it. P10 the questions never contain a confidence figure or a percent (7E). P11 no output starts a second question after the `?`.
- **L6 STATEMENTS ARE WORDED TOO (no staircase leading nowhere, FL3).** J6 and its caller also produce four things the owner must be TOLD, none a question: (a) SAY-READING: J6 `sayReading` true: AXON acted on one of two close readings and says which one and which it set aside (7S SAY-WHEN-UNSURE: in its own words each time, never a template; a clear reading says nothing); (b) DEFAULT-USED: reason code `default-used`: the approved default is said aloud (bind-default rule); (c) BLOCK: `permission-never`: AXON says it will not do it and that the owner's Charter says never (N2: never hides a block); (d) CANNOT-REPAIR: the D3 case (repair limits passed): AXON says plainly it could not repair the message (FL15 loud). A statement has no `?`, 1 to 300 characters (no J2 limit applies; the cap is DLG's own), and uses the same pieces file and the same properties P6 to P10.
- **L7 ONE QUESTION PER TURN STAYS WITH THE CALLER (D1).** The engine words only the question it is given. Questions that wait are NOT worded early: after the owner answers, the whole decision runs again and the next question is worded then (MR1: a split is kept only if every part resolves).
- **L8 THE 200-CHARACTER LIMIT IS A HARD RULE, NEVER A SILENT CUT.** If the chosen frame plus the facts exceed 200, the engine tries the shortest frame of the same kind, then drops optional values from `action`; if it still does not fit it returns the failure `too-long` and the caller shows the plain fallback line "I need to ask you something, but I could not word it. Please check the tool and try again." (fixed safety line, owner approves, FL13). It never cuts a tool name in half. The DLG2 sweep runs every real tool name, every kind and every frame at 4 readings and 4 slots and reports the real maximum (MEASURED then, not guessed).
- **L9 WHAT DLG1 DOES NOT DO.** It does not decide whether to ask (J6), does not choose the slot to ask first (the feed and J6 hand it ONE kind and the missing slots), does not read the owner's answer (Dialogue D1 answer path, `dialogueAnswer.ts`), does not make the Settings notice of the Charter (CHR1: a fixed safety line the owner approves), does not translate.
