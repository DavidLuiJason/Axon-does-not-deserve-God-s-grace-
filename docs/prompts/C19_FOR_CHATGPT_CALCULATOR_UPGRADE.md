THE JOB (deliver 1 to 3 complete and tested; 4 and 5 are part of the same files):

1. PERCENT, like a phone calculator, with exact arithmetic. A `%` directly after a number or `)` is PERCENT when the next token does not begin an operand (not a number, name, function or `(`); otherwise it is the old REMAINDER (`10 % 3` stays 1; `10 %3` stays 1). Rules, with L the whole left expression accumulated so far at that level (left to right):
 - `L + b%` = L + L * b / 100; `L - b%` = L - L * b / 100 (so `200 + 10 + 5%` = 210 + 10.5 = 220.5).
 - In every other place `b%` = b / 100 (`200 * 15%` = 30; `80 / 50%` = 160; a lone `50%` = 0.5).
 - The word `of` between operands means multiplication at the SAME precedence as `*` and left to right, so `15% of 80` = 12 and `50% of 100 times 10` = (50% of 100) times 10 = 500.
 - Accept the word operators `times`, `plus`, `minus`, `divided by`, `over`, `mod`, `x` (only between operands) and the symbols `×`, `÷`, `−`, `–`, `**`.
2. MISSING PARTS: factorial `n!` (integers 0 to 170, exact through BigInt, then converted; a negative, fractional or too large operand is a 'domain' error); `ncr(n,r)` and `npr(n,r)` (exact, integers, cap of n at 1,000, 'domain' otherwise); IMPLICIT MULTIPLICATION (`2(3+4)`, `(1+2)(3+4)`, `2pi`, `3sqrt(4)`, `2sin(30)`; but `2 3` stays a syntax error); the `√` prefix and `π`; `ans` (the previous result, passed as `options.ans`; a syntax error with a plain hint when none exists); scientific input `1e3`, `1.5E-3`; functions asin, acos, atan, sinh, cosh, tanh, exp, log2, cbrt (and the existing ones; `log` stays base 10, `ln` natural); domain errors for asin or acos outside -1..1, ln or log of 0 or less, tan at an odd multiple of 90 degrees. In DEGREE mode use EXACT results for sin, cos and tan at multiples of 30 and 45 degrees (sin(30) = 0.5 exactly, cos(90) = 0, sin(180) = 0, tan(45) = 1) by reducing the angle modulo 360 first; elsewhere use Math.
3. "READ AS": every successful result and every error includes `interpreted: string`, the expression rewritten in plain explicit form that shows how it was read, for example `200 + 10%` becomes `200 + (200 × 10 ÷ 100)` and `50% of 100 times 10` becomes `((50 ÷ 100) × 100) × 10`; errors include a plain `hint` ("A % needs a number before it", "I did not understand the word 'of' here") and the `position`. The screen will show this line. It is how a wrong reading can never hide.
4. COMPATIBILITY: every expression the OLD engine accepted must give the SAME value and the same formatting. Prove it: keep a copy of the old file under tests/helpers/calculatorOld.ts (test-only) and compare old and new on at least 5,000 generated expressions (numbers, + - * / ^ %, parentheses, unary signs, the old functions and constants); list any difference and justify it, or fix it. Limits stay: 512 characters, 256 tokens; add a parenthesis depth cap of 64 and a work bound so nothing can hang.
5. Keep `CALCULATOR_DESCRIPTOR` valid for `tests/engineTruth.test.ts` (do not change its toolId or actions without checking that test); extend the descriptor's text only if the test allows.

TESTS (`tests/calculatorUpgrade.test.ts`): expected values derived by an INDEPENDENT Python implementation using `fractions.Fraction` of the percent, `of` and factorial rules above (not remembered, not copied from the engine), on at least 500 generated expressions covering every form; plus an explicit table that the test derives with Python: `50% of 100 times 10` = 500; `100 + 10%` = 110; `100 - 10%` = 90; `200 * 15%` = 30; `15% of 80` = 12; `80 / 50%` = 160; `50%` = 0.5; `200 + 10 + 5%` = 220.5; `10 % 3` = 1; `5!` = 120; `0!` = 1; `171!` domain; `2(3+4)` = 14; `2pi` = 6.28318530717959; `sqrt(16)+3!` = 10; `ncr(5,2)` = 10; sin(30) deg = 0.5; cos(90) deg = 0; tan(90) deg domain; `ans*2` with ans 21 = 42; `1e3+1` = 1001; asin(2) domain; ln(0) domain.
