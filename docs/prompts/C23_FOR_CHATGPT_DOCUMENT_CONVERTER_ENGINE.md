## JOB C23: DOCUMENT CONVERTER ENGINE (docx, txt, md, html)

FILES THAT MUST EXIST (stop and say which is missing): src/tools/engines/files/zipTool.ts (`createZip`, `listZip`, `extractEntry`), src/tools/engines/data/xml.ts (`parseXml`), src/tools/engines/text/markdown.ts, src/tools/engines/text/htmlText.ts and src/tools/engines/text/textFormats.ts (read their real exports first and reuse them; do not write a second Markdown or HTML reader), src/tools/engines/files/documentRead.ts (the Document Reader engine).

WHAT TO BUILD (priority order; deliver finished items complete):
1. `src/tools/engines/files/docxRead.ts` exporting `readDocx(bytes: Uint8Array): Promise<DocxReadResult>`: opens the zip through `extractEntry` (so every size and ratio cap of the zip tool applies), reads `word/document.xml` (and `word/styles.xml` only to learn heading, list, bold and italic styles), and returns `{ ok: true; blocks: Block[]; plainText: string; markdown: string; losses: string[] }`. `Block` = heading (level 1 to 6), paragraph, list item (ordered or bullet, level), table (rows of cell text), with inline runs (bold, italic, link text). Header, footer, comments, footnotes, images, text boxes, tracked changes, fields and equations are NOT read: each kind that is present in the file adds one plain line to `losses` (for example "2 images were not included"). An encrypted file, a file that is not a zip, a zip without `word/document.xml`, and a file over the caps return typed errors, never a throw.
2. `src/tools/engines/files/docxWrite.ts` exporting `writeDocx(source: { format: 'txt' | 'md' | 'html'; text: string; title?: string }): Promise<DocxWriteResult>` returning `{ ok: true; bytes: Uint8Array; losses: string[] }`: a real Word file with `[Content_Types].xml`, `_rels/.rels`, `word/document.xml`, `word/styles.xml` (Normal, Heading 1 to 6, List Bullet, List Number, Hyperlink, Table Grid) and `word/_rels/document.xml.rels`, built with the zip tool. Markdown headings, paragraphs, bold, italic, links (visible text plus a real hyperlink), bullet and numbered lists, simple tables and code blocks (monospace) are kept. HTML goes through the existing HTML reader FIRST and is NEVER passed through as markup (scripts and styles dropped; say so in `losses`). Everything is XML-escaped; control characters are removed with a loss line; emoji and right-to-left text are kept.
3. `src/tools/engines/files/documentConvert.ts` exporting `planDocumentConversion` and `convertDocument` over the pairs: docx to txt, docx to md, txt to docx, md to docx, html to docx. Every unsupported pair (pdf, doc, odt, rtf, pages, to or from) returns the typed error `unsupported-pair` with one plain sentence naming what IS supported. Every success returns the one-line `lossLine` the Converter pattern requires (what was lost or changed, or "Nothing was lost.").
4. `DOCUMENT_CONVERTER_DESCRIPTOR` with toolId `document-converter` (the exact catalog id), honest purpose, two examples.

PROOF (derive independently):
- Reference files: generate at least 12 .docx files with an independent tool in YOUR sandbox (Python `python-docx`, or LibreOffice headless if present; say which) covering headings, lists, nested lists, bold, italic, links, tables, a page with an image, a footnote, tracked changes, emoji, Arabic or Hebrew text, a very long paragraph; save them as `tests/fixtures/docx-*.docx` (each under 60 KB, total under 400 KB). `readDocx` must return the plain text and markdown that you derive independently (python-docx reading the same file) and must report loss lines for the parts it skips.

- Hostile input: a zip-bomb docx (high ratio), a docx with `../` entry names, a billion-laughs style XML, a 5 MB single paragraph, empty files, a text file renamed .docx: typed errors, bounded time, no throw.
- Mutation check: stop escaping `&` and `<` in `writeDocx` on purpose and show the tests fail; restore it.
