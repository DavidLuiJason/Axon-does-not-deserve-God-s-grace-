## JOB C17: FILE CONVERTER AND BATCH CONVERT PLANNERS

FILES THAT MUST EXIST IN THE BASE (stop and say which is missing): src/tools/converter/kinds.ts (kinds 'data-formats', 'text-formats', 'image'), src/tools/converter/convert.ts, src/tools/converter/blocks.ts, src/tools/engines/images/convertPlan.ts (planImageConversion, planBatchNames, IMAGE_CONVERT_LIMITS), src/tools/engines/files/inspect.ts (inspectBytes), src/tools/engines/files/zipTool.ts (createZip, ZIP_TOOL_LIMITS), src/tools/engines/data/csv.ts, src/tools/engines/text/markdown.ts, tests/convertBlocks.test.ts, tests/toolsConverter.test.ts. READ kinds.ts and convert.ts FIRST: format ids and what each conversion loses come from them. NEVER copy a format list into the new files: derive it from kinds.ts so that a new format added there appears here automatically.

PRIORITY ORDER (deliver both; if you truly cannot, deliver the first complete):

1. FILE CONVERTER PLANNER. `src/tools/engines/files/fileConvertPlan.ts`, test `tests/fileConvertPlan.test.ts`. Pure; it never reads a whole file, only `{ name, size, head: Uint8Array }` (first 4096 bytes).
 a. `detectConvertible(file)` returns `{ ok: true, family: 'data' | 'text' | 'image' | 'unsupported', kindId, formatId, reason }`: by extension first, then the content head (use inspectBytes); a name and content that disagree give a `warnings` entry (for example a `.json` file that starts like a PNG), and the content wins for images. Unknown or unsupported files return a plain message naming what they are when known ("This is a PDF. AXON cannot convert PDFs yet.").
 b. `targetsFor(kindId, formatId)` returns the formats this one can become, taken from kinds.ts, never itself. SVG is never offered as an output.
 c. `planFileConversion(file, to, options?)` returns `{ ok: true, kindId, from, to, outputName, outputMime, mode: 'text' | 'image', losses: string[], limitsOk: true }` or a typed error. `outputName`: replace the extension, keep the base name, handle names with several dots, a dot-file, no extension, path separators and control characters (removed), a length cap in code points; the result must never equal the input name. `losses` are plain sentences taken from what the conversions really do ("Comments are dropped.", "Picture details such as location are removed.", "JPG and WebP lose a little quality each time."). Check the size against the real limit constants of the engine involved (CSV_LIMITS, MARKDOWN_LIMITS, HTML_TEXT_LIMITS, IMAGE_CONVERT_LIMITS ...) and return 'too-large' with the limit in the message.
 d. Export `FILE_CONVERTER_DESCRIPTOR` with toolId 'file-converter'.

2. BATCH PLANNER AND RUN. `src/tools/engines/files/batchPlan.ts`, test `tests/batchPlan.test.ts`. A batch converts MANY files to ONE target format.
 a. `planBatch(files, to)`: each file becomes `{ id, name, status: 'ready' | 'skipped', reason?, outputName }`; a file that cannot become `to` is skipped with a plain reason ("A PNG cannot become YAML."). Output names are unique case-insensitively (second one `name-2.ext`, third `name-3.ext`, never overwriting an input name in the list). Exported `BATCH_LIMITS`: 50 files, 100 MiB total, 30 image files; over a limit gives a typed error that says which limit.
 b. `createBatchRun(plan, options?)` is a PURE state machine the screen drives: `next()` returns the next ready item or null; `complete(id, { ok, bytes?, message? })`; `cancel()`; `snapshot()` returns counts (ready, done, failed, skipped), percent, and state 'idle' | 'running' | 'cancelled' | 'done'. To protect a weak phone it holds finished outputs only up to `maxHeldBytes` (default 64 MiB): when the next `complete` would exceed it, it returns `{ ok: false, error: 'memory-cap' }` and the screen must `drain()` (returns the held outputs and releases them) before continuing. `complete` for an unknown id, twice for the same id, or after cancel are typed errors, never a crash.
 c. `batchReport(run)` returns structured rows `{ name, result: 'converted' | 'failed' | 'skipped' | 'cancelled', sizeBefore, sizeAfter?, note }` and a plain-text copy; `zipEntries(rows)` returns the `{ name, bytes }` list ready for `createZip`, refusing duplicate names.
 d. Export `BATCH_CONVERT_DESCRIPTOR` with toolId 'batch-convert'.
 TESTS: expected values derived independently (Python for names, counts and totals); name collisions in every case combination; limits; every state transition including illegal ones; a seeded random walk of 2,000 operations that never breaks an invariant (done + failed + skipped + remaining = total).
