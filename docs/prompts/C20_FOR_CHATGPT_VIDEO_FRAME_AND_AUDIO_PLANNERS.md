## JOB C20: VIDEO FRAMES AND VIDEO TO AUDIO PLANNERS (PURE; NO VIDEO IS DECODED HERE)

WHY: the owner wants (a) a tool that extracts pictures from a video: all of them, only chosen ones, every 5 seconds or every 2 seconds, every 1 frame or every 40 frames, particular frames, or from one part of the video to another; and (b) a tool that turns a video into audio. What a phone can actually decode is measured separately (a probe the owner runs); THIS job only builds the planning logic, which must not assume any capability.

FILES THAT MUST EXIST IN THE BASE (stop and say which is missing): src/tools/engines/images/convertPlan.ts (planBatchNames, IMAGE_CONVERT_LIMITS: reuse its naming ideas), src/tools/engines/files/zipTool.ts (ZIP_TOOL_LIMITS), src/tools/engines/files/inspect.ts, tsconfig.json. If the BASE already contains src/tools/engines/files/batchPlan.ts (job C17), read it and reuse its run state machine PATTERN; do not import across unmerged work.

PRIORITY ORDER (deliver both; if you truly cannot, deliver the first complete):

1. FRAME PLANNER. `src/tools/engines/video/framePlan.ts`, test `tests/framePlan.test.ts`.
 a. `parseTime(text)` accepts `83.5`, `1:23.5`, `01:02:03`, `1h2m3s`, `2m`, returns milliseconds or a typed error with a plain message; negative, empty, more than 48 hours and nonsense are errors.
 b. Input `video = { durationMs, fps, width, height, frameCount? }` (fps may be fractional such as 29.97 or 23.976; durationMs at least 1; fps greater than 0 and at most 240; width and height at least 1). Source frame numbering: `frameNumber = floor(timeMs * fps / 1000 + 1e-9)`; the last frame is `max(0, ceil(durationMs * fps / 1000) - 1)` (or `frameCount - 1` when given); a frame's time is `round(frameNumber * 1000 / fps)` ms.
 c. `planFrames(video, spec)` where `spec` is one of: `{ mode: 'all' }`; `{ mode: 'everyNFrames', n }` (n a positive integer); `{ mode: 'everyNSeconds', seconds }` (0.001 or more, fractions allowed, for example 0.5 or 2 or 5); `{ mode: 'specific', timesMs?: number[], frames?: number[] }`; `{ mode: 'count', count }` (evenly spaced, first and last included when count is 2 or more); each may carry `range: { startMs, endMs }` (start inclusive, end exclusive, inside the video) and `maxFrames`. Result `{ ok: true, frames: { index, frameNumber, timeMs }[], warnings: string[], skipped: string[], estimate: { count, pngBytes, jpgBytes } }` where the byte estimates are rough and LABELLED estimates (width x height based; say so in the field name or a `note`). Out-of-range or duplicate requested frames are skipped with a reason, never silently dropped; duplicates by frameNumber appear once; the list is in time order.
 d. LIMITS: exported `FRAME_LIMITS = { absoluteMax: 5000 }` and `maxFramesForTier(tier)` for tiers 'low' (300), 'mid' (1500), 'high' (5000) (the Device Profile tool will supply the tier; you only take it as a parameter). When the plan exceeds the tier's cap return `{ ok: false, error: 'too-many', count, cap, suggestion }` where `suggestion` is a plain sentence with a concrete step that WOULD fit (for example "every 8 seconds gives 150 pictures"), computed, not canned. Never allocate a list longer than the cap while counting (compute the count arithmetically first).
 e. `frameFileNames(baseName, frames, format)` ('png' | 'jpg' | 'webp'): `name_f000123_00-00-05.120.png` style, frame number zero-padded to the width of the largest, time as hh-mm-ss.mmm, base name sanitised (control characters and path separators removed, length cap in code points), unique, never empty.
 f. `createFrameRun(plan, { maxHeldBytes })`: a PURE state machine like a batch: `next()` returns the next frame to grab or null; `complete(index, { ok, bytes?, message? })`; `cancel()`; `snapshot()` (counts, percent, state 'idle' | 'running' | 'cancelled' | 'done'); when held output would exceed `maxHeldBytes` (default 48 MiB) `complete` returns `{ ok: false, error: 'memory-cap' }` until `drain()` hands back and releases the held outputs; `report()` returns plain text and rows; illegal calls (unknown index, twice, after cancel) are typed errors. `zipEntries(rows)` returns `{ name, bytes }` ready for `createZip`, refusing duplicates.
 g. Export `VIDEO_FRAMES_DESCRIPTOR` (toolId 'video-frames') as a plain object; DO NOT register it anywhere and DO NOT edit the catalog or registry (a later job wires them).

2. AUDIO EXTRACTION PLANNER. `src/tools/engines/video/audioPlan.ts`, test `tests/audioPlan.test.ts`.
 a. Input `{ durationMs, container, audioCodec, bitrate?, sampleRate?, channels?, rangeMs? }` and a `capabilities` object that the CALLER supplies from what the phone was measured to do: `{ copyTrack: boolean, encode: ('wav' | 'mp3' | 'aac')[] }`. Never assume a capability.
 b. `planAudioExtract(input, to, capabilities)` returns `{ ok: true, mode: 'copy' | 'reencode', outputExt, outputMime, lossless: boolean, estimatedBytes, note }` or a typed error 'unsupported' with a plain reason. Rules: COPY (no quality loss, fast) is planned when `capabilities.copyTrack` is true and the codec has a matching container (aac to m4a, mp3 to mp3, opus or vorbis to ogg, flac to flac) and `to` is 'original'; `to: 'wav'` is a re-encode to 16-bit PCM and is possible only when 'wav' is in `capabilities.encode` (size = sampleRate x channels x 2 x seconds); 'mp3' and 'aac' likewise only when listed (size = bitrate x seconds / 8, default 128 kbps, labelled an estimate); a time range changes the size estimate; a video with NO audio track (`audioCodec` null) is a plain error 'no-audio'. Sizes are labelled estimates in the field name or `note`.
 c. Export `VIDEO_TO_AUDIO_DESCRIPTOR` (toolId 'video-to-audio'); same rule: do not register or edit anything else.

TESTS: expected values derived by an INDEPENDENT Python implementation of the rules above (frame numbers, counts, times, sizes) on at least 300 generated cases (fps 23.976, 24, 25, 29.97, 30, 60, 0.5-second steps, ranges, specific lists with out-of-range and duplicates, a 3-hour video at 60 fps with `everyNFrames` 1 that must return 'too-many' for every tier without building a list); every error; the run state machine through a seeded random walk of 2,000 operations that never breaks the invariant done + failed + remaining = total; mutation tests (at least 5).

LANE: NEW src/tools/engines/video/framePlan.ts, src/tools/engines/video/audioPlan.ts, tests/framePlan.test.ts, tests/audioPlan.test.ts, docs/reports/C20_REPORT.md. Nothing else.
