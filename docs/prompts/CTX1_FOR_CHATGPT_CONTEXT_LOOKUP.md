## JOB CTX1: one export in `src/decision/contextLookup.ts`

**Style:** follow `src/decision/actOrAskFeed.ts`: pure function; NO `Date`, `Math.random`, `fetch`, `console`, storage, global state, regex literals or phrase lists. NO imports at all in the engine file (declare the `EngineResult` type locally the way the neighbours do). Inputs are never changed. "Exact keys" checks count string AND symbol own keys (`Reflect.ownKeys`). Every result is deep-frozen (`Object.freeze`, arrays and nested objects too), the error result as well. The function takes `unknown`, never throws (any exception: `bad-input`), returns `{ok:true,value}` or a frozen `{ok:false,error,message}` with the ONE message `Context lookup input is invalid.`

```ts
export function lookupContext(input: unknown): EngineResult<ContextLookupValue>;
// input: { missing: {slot:string, kind:Kind}[], items: ContextItem[] }   (exactly these two keys)
// Kind = 'text'|'choice'|'file'|'number'|'yes-no'|'duration'|'time'|'date'
// ContextItem = { id, source, kind, slot?, readable? }  source = 'selected'|'attached'|'previous-reference'|'answer'
```
Also export the types `ContextKind`, `ContextSource`, `ContextItem`, `MissingSlot`, `ContextTraceEntry`, `ContextLookupValue`.

**Validation, first failing step wins** (the exact meaning is in `docs/CTX1_CASES.md` section C): (1) not a non-array object: `bad-input`; (2) keys not exactly `missing`, `items`: `unknown-key`; (3) `missing` invalid (not an array; an entry not exactly `{slot, kind}`; empty slot; kind outside the eight; a repeated slot): `bad-missing`; (4) `items` invalid: `bad-items`. An item has exactly the keys `id`, `source`, `kind`, PLUS `slot` when the source is `answer` (non-empty string, required, forbidden otherwise), PLUS `readable` (boolean) when the source is `attached` AND the kind is `file` (required, forbidden otherwise). `id` is a non-empty string, distinct across all items; the source must be one of the four (no other source exists: notes are not a source); (5) a source over its cap (selected 4, attached 8, previous-reference 8, answer 8, counted per source): `too-many-items`. An empty `missing` and an empty `items` are valid.

**The rules, per missing slot, in the order of the input; the FIRST rule that finds candidates decides, and an ambiguous case stops there (unsure goes UP, never to a later rule):**
- **R1 answer.** `answer` items with the same `slot` name AND the same kind as the missing slot. One: filled from context. Two or more: ambiguous, stop.
- **R0 decision slots.** If no R1 candidate and the kind is `choice` or `yes-no`: not filled, rule `R0`, reason `decision-slot` (a choice is a decision: never guessed from an object or an old value). (Mind the order: R1 is looked at FIRST for every slot, R0 only decides what happens when R1 found nothing. Rows C7 to C10 show it.)
- **R2 selected**, then **R3 attached**, then **R4 previous-reference**: items of that source whose kind equals the slot's kind. One: filled from context (an attached `file` item fills a `file` slot whatever its `readable` value). Two or more: ambiguous, stop. None: next rule.
- **R5 safe step.** Only a `text` slot that found nothing in R1 to R4: the `attached` items of kind `file` with `readable` true: exactly one: the slot goes to `safeStepFills` (a later read-only step turns that file into text); two or more: ambiguous; none: no candidate.
- A slot found by R1 to R4 is in `contextFills`; by R5 in `safeStepFills`; never both. Both lists keep the input order of `missing`. Each slot is judged ALONE: one item may fill two slots (rows C28, C29b); nothing is "used up".

**Value (key order matters):** `{contextFills: string[], safeStepFills: string[], trace}`; `trace` has one entry per missing slot, in order, keys in this order: `slot`, `outcome` (`'context'`|`'safe-step'`|`'not-filled'`), `rule` (`'R0'`..`'R5'` or `'none'`), `itemId` (the filling item's id, else `null`), `reason` (`'ok'`|`'ambiguous'`|`'no-candidate'`|`'decision-slot'`). Not filled with nothing found (no candidate anywhere): rule `'none'`. Not filled and ambiguous: the rule that was ambiguous. Filled: the rule that filled it.
