PRIORITY ORDER (deliver all three; if you truly cannot, deliver the first N complete):

1. ENTRIES AND STORE. `src/tools/engines/dictionary/userDictionary.ts`, test `tests/userDictionary.test.ts`.
 a. Entry `{ id, word, key, partOfSpeech: 'noun' | 'verb' | 'adjective' | 'adverb' | 'other', meaning, example?, synonyms?, addedAt, source: 'typed' | string }`. `key` = NFKC, lower-case, trimmed, inner spaces collapsed; a headword has 1 to 5 words and at most 60 characters, no control characters; meaning at most 500 characters; example at most 300; at most 10 synonyms of at most 60. `id` is a stable hash of key plus part of speech (injected hash function; the test supplies one).
 b. `createUserDictionary(storage, options)`: `storage` injected (get, set, remove), key `axon.userdict.v1`, schema version inside the value, safe when storage is missing or corrupt, caps `USER_DICT_LIMITS`: 20,000 entries and 3 MB serialised, typed error when exceeded. Operations: add, update, remove, get(key), find(prefix, limit), list(offset, limit), count, exportJson, exportCsv (header word, part_of_speech, meaning, example, synonyms with `;`), eraseAll({ force }) (force recovers from corrupt, oversized or newer-schema data, as in toolStore), and ONE-LEVEL UNDO: `undoLast()` restores the copy taken before the last import, bulk remove or eraseAll. A newer schema version is read-only with a plain message; a migration function from a fake version 0 is tested.
 c. Time is injected (`now`), never read from the clock.

2. STAGED IMPORT. `src/tools/engines/dictionary/userDictionaryImport.ts`, test `tests/userDictionaryImport.test.ts`.
 a. `parseImport({ name, bytes }, context)` where context = `{ existing: (key, pos) => boolean, coreHas: (key) => boolean }` (both injected; the English dictionary is only ever asked, never changed). Formats: TXT (one entry per line as `word: meaning`, `word - meaning` or `word<TAB>meaning`; lines starting with `#` and blank lines ignored), CSV or TSV (header names word, meaning, and optionally part_of_speech, example, synonyms), JSON (an array of objects with the same names, or an object mapping word to meaning), and ZIP holding any of these (use zipTool limits; at most 20 supported entries; unsupported entries are listed as ignored). `parseImportChunks` is the same work as an async generator that yields between files and every 1,000 rows so a screen can show progress and cancel.
 b. NOTHING IS STORED by parsing. It returns `ImportReport { accepted: Entry[], duplicates: {where, word, reason}[] (same key and part of speech twice in the file: keep the first; or already yours), alsoInCore: string[] (informational: the core dictionary has it; it is still accepted as the owner's own entry), rejected: {where (line, row or path), reason, text (cut to 80 characters)}[], ignored: string[], stats }`. Plain reason codes and messages (empty word, too long, bad part of speech, control characters, too many entries, file too large ...). Limits exported (file 5 MiB, 20,000 rows).
 c. `applyImport(dictionary, report, { confirm, replaceExisting })`: does NOTHING and returns a typed error unless `confirm === true`; takes the undo copy first; returns counts added, replaced, skipped.
