## THE JOB

MINI-BASE: `src/brain/mind/memory/notes/notesTypes.ts` (the contract: READ FIRST, do not change; it holds the types, the three label strings and the 13 function shapes), `src/brain/mind/memory/notes/notes.ts` (a STUB that throws: you replace the whole file), `tests/memoryNotesRunner.test.ts` (THE PROOF: read it, do not change it), `tests/valuesGuard.test.ts` (FL13 guard), `run.mjs` and `register.mjs` (the runner, no install), `tsconfig.values.json`.

### Rules for every function
Pure: never change an argument (the runner freezes every store deeply), return NEW store objects (notes that did not change may be shared), never throw, never read a clock (the caller passes `now`), no import except `./notesTypes`. A "bad store" is anything that is not an object with `version` 1, an integer `nextId` of at least 1 and arrays `topics` and `notes` (a quick shape check, not a full check). A "finite number" means `Number.isFinite`. A VALID CONSENT is an object whose `kind` is one of the consent labels and whose `at` is a finite number; a stored consent is always a fresh copy `{kind, at}`. Labels: import `NOTE_KIND_LABELS`, `NOTE_STATE_LABELS`, `CONSENT_KIND_LABELS` and use `.split(' ')`; never write the words again (FL13). Ids: ONE counter. A new topic gets `t` + `nextId`, a new note gets `n` + `nextId`, each use adds 1 (a note made with a new topic: topic first, then note).

1. `emptyStore()` returns `{version: 1, nextId: 1, topics: [], notes: []}`, a new object each time.
2. `topicKey(name)`: a non-string gives ''. Otherwise every run of white space (a character c with `c.trim() === ''`) becomes ONE space, white space at both ends is dropped, and each UTF-16 unit is lowered with `unit.toLowerCase()`, except that a unit whose lowercase is not exactly one unit stays as it is. No other change ("C++" stays "c++"). The topic NAME stored for a new topic is the same text with the white space collapsed but the case kept.
3. `proposeNote(store, input, now)`. Checks in THIS order: bad store, `now` not finite, input not an object, topic or text not strings, kind not a label, `standalone` not a boolean, source not `{text: string, chat: string|null}` give `bad-input`; `standalone` false gives `not-standalone` (a note from an "if" or reason clause is never proposed); empty `topicKey(topic)` gives `empty-topic`; text empty after trim gives `empty-text`; kind 'meaning' with a term that is not a string or is empty after trim gives `missing-term`. Stored text and term are trimmed; a term is stored only for kind 'meaning' (null otherwise, whatever was passed). DUPLICATE: when a note of ANY state already exists in the same topic (same key), with the same kind, the same `topicKey(text)` and the same `topicKey(term)` (null equals null), return `{ok: true, store: <same store>, note: <that note>, changed: false}`. Otherwise find the topic by key or make it (`created` = now), then add the note: state 'proposed', `consent` null, `created` = `changed` = now, `history` [], `source` a copy. Result `changed: true`.
4. `keepNote(store, id, consent, now)`. Order: bad store, id not a string, `now` not finite give `bad-input`; invalid consent gives `no-consent`; unknown id `not-found`; state 'removed' `wrong-state` (a removed note is restored, not kept); state 'kept' gives ok, `changed: false`, same store; state 'proposed' becomes 'kept' with the consent copy and `changed` = now.
5. `discardProposal(store, id)` (the owner said no to a proposal): bad store or id not a string `bad-input`; unknown `not-found`; state not 'proposed' `wrong-state`; else the note is deleted, and its topic too when no note is left in it. `note` in the result is the deleted note, `changed: true`.
6. `removeNote(store, id, now)`: bad input as in 4; unknown `not-found`; 'proposed' `wrong-state`; 'removed' ok unchanged; 'kept' becomes 'removed', `changed` = now, consent stays.
7. `restoreNote(store, id, now)`: the mirror: 'proposed' `wrong-state`; 'kept' ok unchanged; 'removed' becomes 'kept', `changed` = now, the old consent stays.
8. `correctNote(store, id, edit, consent, now)` changes a KEPT note. Order: bad store, id not a string, edit not an object, `now` not finite, `edit.text` or `edit.topic` present but not a string, `edit.term` present but neither a string nor null give `bad-input`; invalid consent `no-consent`; unknown `not-found`; state not 'kept' `wrong-state`; `edit.text` given and empty after trim `empty-text`; for a 'meaning' note `edit.term` given and null or empty after trim `missing-term` (for other kinds `edit.term` is ignored); `edit.topic` given and empty key `empty-topic`. The new values: text and term trimmed, the destination topic found by key. UNCHANGED (same text, same term, destination is the note's own topic): ok, `changed: false`, same store, no topic made. DUPLICATE: if another note would then match the same (topic key, kind, `topicKey(text)`, `topicKey(term)`) give `duplicate`. Otherwise apply: append `{text, term, topic (the old topic ID), changed}` of the OLD note to `history`; set the new text, term and topic (a missing destination topic is made with `created` = now); `changed` = now; `consent` = a copy of the new consent. When the note moved and the old topic has no note left, delete that topic. `changed: true`.
9. `listNotes(store, options?)`: a bad store gives []. `options` undefined means states `['kept']`; `options` not an object, or `options.states` present but not an array of state labels, gives []. Result: one `{topic, notes}` per topic that has at least one note in those states, the notes being only those; topics ordered by `key` (plain `<` comparison of the strings), ties by the number in the id; notes ordered by `created`, ties by the number in the id.
10. `findInMessage(store, text)`: bad store or non-string text gives []. Only KEPT notes count. Normalise the text: a run of white space becomes one space, white space at both ends is dropped, each unit lowered as in rule 2; keep a map from each normalised character to its index in the ORIGINAL text (a collapsed run maps to the index of its first white-space character). Candidates, by KEY: (a) every topic that has a kept note: its key; (b) every kept 'meaning' note: `topicKey(term)`. Empty keys are skipped. One candidate per distinct key; its notes are the kept notes of the topic with that key plus the kept 'meaning' notes whose term has that key, no note twice, ordered as in rule 9; if a topic has that key the mention is `via: 'topic'` and `topic` is that topic's id, otherwise `via: 'term'` and `topic` is the topic id of the first note. Take candidates longest key first (ties: plain string order). Look for each key in the normalised text; an occurrence counts only when the character before it and the character after it (if any) are NOT word characters (a word character is a digit 0-9 or a character with `c.toLowerCase() !== c.toUpperCase()`) and no character of it is already taken by an earlier mention. Continue searching after an accepted occurrence; after a rejected one start again one character later. A mention is `{start, end, text, topic, via, notes (ids)}` where `start` = map of the first character, `end` = map of the last character + 1, `text` = the original text between them (so "Liquid   app" keeps its inner spaces). Return the mentions in order of `start`.
11. `dictionaryCandidate(store, id)`: for a KEPT note of kind 'meaning' return `{term, meaning: text}`; anything else, or a bad store, gives null. It only LOOKS: nothing in memory notes ever writes to the dictionary (the owner must say "add this to my dictionary").
12. `serializeStore(store)`: a bad store gives ''. Otherwise `JSON.stringify` of an object built field by field in the EXACT order of the types, with no spaces: store `version, nextId, topics, notes`; topic `id, name, key, created`; note `id, topic, kind, text, term, state, source {text, chat}, created, changed, consent (null or {kind, at}), history`; history item `text, term, topic, changed`.
13. `parseStore(text)`: not a string, or not valid JSON, gives `{ok: false, reason: 'bad-text'}`. Valid JSON that breaks any STORE RULE gives `{ok: false, reason: 'bad-store'}`. Otherwise `{ok: true, store}`, the store built fresh in the order of rule 12 (unknown extra keys are dropped), so `serializeStore(parse(x).store) === x` for any text that serializeStore wrote.

### STORE RULES (parseStore checks all nine; the runner's own checker uses them after every step)
S1 version 1; `nextId` an integer of at least 1 and greater than the number in every id; `topics` and `notes` arrays. S2 topic ids are `t` + a positive integer without leading zeros, note ids `n` + the same; all ids differ (topics and notes together). S3 a topic's `name` is not empty, has no outer or doubled white space, `key` equals `topicKey(name)`, keys differ, `created` is finite. S4 every topic has at least one note. S5 a note's topic exists; kind and state are labels; text is not empty and has no outer white space; `created` and `changed` are finite; `source.text` is a string and `source.chat` a string or null. S6 a 'meaning' note has a non-empty trimmed term, every other kind has term null. S7 `consent` is null exactly when the state is 'proposed', otherwise a valid consent. S8 `history` is an array of `{text: string, term: string|null, topic: string, changed: finite}`. S9 no two notes share (topic, kind, `topicKey(text)`, `topicKey(term)`).
