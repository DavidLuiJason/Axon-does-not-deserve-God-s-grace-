AXON WEB (= AXON BROWSER) - SCREEN READINESS
From: Director 204 (D204), lane AXON Web. Date: 2026-11-16 (updated after WEB6 to WEB9).
For: whoever directs the screens (AI Studio screens prompt). D204 knows screens are being built and wrote this so screens are built only on parts that exist.
Base: repo of 2026-11-11 plus D204 rounds up to WEB8. D204 has no newer copy.

1. WHAT AXON WEB IS
AXON Web and AXON Browser are one thing. It is a real browser, and AXON must be able to drive it like a person (open, read, scroll, click, type) under permission rules. Sign-in and payment steps always ask the owner.

2. DESIGN RULES FROM THE OWNER (screens must follow)
- NO search bar and no search window. The chat/prompt box is where the owner searches. The floating button above the chat box is customizable: one tap switches between talking to AXON and searching with AXON Web; other taps or holds can do other things; it can behave differently on different pages.
- Bookmarks and history sit behind the 3-dot menu. Site permissions and security details belong in Settings.
- NO button clutter. An earlier version was scrapped for that. Keep the screen calm and organised.
- Three tab kinds: normal, incognito (disappears when closed), stealth (a separate saved identity per tab; the same site open twice must count as two separate visitors). Leave room for a kind picker on new tab and a small badge on every tab. Stealth details come later from the owner.
- Tab groups like Chrome: create, name, add a tab, remove a tab, delete a group.
- One shared, visible but quiet indicator for when AXON itself controls the screen. It must match the design and be the same for AXON Web, AXON Apps, AutoClicker and anything else where AXON takes over.

3. WHAT EXISTS TODAY (state honestly)
REAL, compiled by the cloud (WEB6, WEB7) or written and tested only in simulation (WEB8), NEVER run on a phone:
 - A native Android browser screen (BrowserActivity) started by the Open browser button on the Web tab (src/components/browser/BrowserHomeScreen.tsx).
 - Tab groups: create, rename, move in, move out, delete (tabs stay), close, list.
 - Incognito tabs (nothing kept), a stealth flag (a separate identity per tab: saved on normal tabs, wiped on incognito tabs), and the default-mode setting normal or stealth (getSettings / setDefaultMode). Needs the Android multi-profile WebView feature; refused honestly if missing. Stealth is isolation only: no IP, user-agent or fingerprint changes.
 - The owner's commands: see docs/AXON_WEB_COMMAND_STATUS_D204.txt for every one of the 130 (built, partial, not applicable with the reason, open). A screen calls them through host.controller.execute from createAndroidAxonWebHost() (src/web/androidAxonWebHost.ts); the permission gateway decides first.
 - AXON's own browsing tab (WEB8): src/web/axonWebAgent.ts with an owner panel (approvals, extra steps, take-over). See docs/AXON_WEB_BRAIN_HOOKUP_D204.txt. The native tab shows "AXON is browsing" and tabs carry axon: true.
REAL LOGIC, tested with simulated engines: the permission gateway (130 commands), page-to-text, link analysis, saved sources, step guard, the AXON agent (about 300 tests in all).
NOT BUILT / NOT PROVEN:
 - Every screen (the owner screens for approvals, the indicator, tab groups, stealth settings, the floating button behaviour, the 3-dot menu, Web settings).
 - The brain/tool hookup (the tools Director registers the web.* tools; the agent is ready).
 - Any test on a phone or on live sites. Tab groups and incognito are not saved across restarts for incognito by design.
 - Open commands: QR code for the page, and install as an app. Partial: per-site permission decisions (saved, but WebView still denies camera, microphone and location until the app declares those permissions), the new-tab page choice.

4. WHAT A SCREEN MAY SAFELY CALL NOW
Anything in the real list above, through the gateway so the permission result is shown. For AXON's tab use only the owner panel handle (owner.pending, approve, deny, allowMore, takeOver) and agent.state() for the indicator. Show a disabled or "coming soon" state for everything in the NOT BUILT list; do not pretend it works.

5. WHAT THE SCREEN DIRECTOR SHOULD ASK D204
The exact result shape of any method (src/web/browserPluginTypes.ts) and when a missing part will exist.
