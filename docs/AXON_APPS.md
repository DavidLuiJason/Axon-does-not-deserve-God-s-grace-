# AXON APPS (D47, 2026-11-14)
PLAIN: AXON can see the apps installed on the phone, open one, read its screen, and move through it (tap, scroll, type, Back, Home), one safe step at a time, then say in plain words what happened. Reading is allowed; typing, switches, anything that pays, sends, deletes or signs in, and every money, wallet or password app ask the owner first (roadmap 7R). It plans nothing itself: the brain or the owner decides the steps.
PIECES (all new, isolated, no caller yet):
- src/axon-apps/app-catalog.mjs: clean the raw app list, search it (exact, starts with, contains, package, similar spelling), never guess between equal matches, flag money/wallet/password apps (SENSITIVE_PATTERNS, owner-editable; includes common Nigerian fintech and bank names).
- src/axon-apps/apps-source.mjs + apps-native.ts: wrapper for the native AxonApps plugin (list, open, icon, app settings); every call fails safe.
- src/axon-apps/apps-controller.mjs: listApps, open, see, tap, longPress, toggle, type, scroll, back, home, approve, run(steps) with stop-and-resume at every question, stop(), a plain-words activity log (typed text is never in results or the log), a step cap (30), settle-waiting after each action, and a one-line "what changed" report.
- android-overlay/.../apps/AppsPlugin.java: lists launchable apps through a narrow launcher query (no broad all-packages permission), opens an app (through the accessibility service when it is running, so it can work from the background), small icon on request, opens an app's settings page. It cannot uninstall, clear or change anything.
- screen-actor.mjs / action-gate.mjs (D47's own): open-app is now real; askPackages makes sensitive apps ask before opening and before any tap or typing inside them (scrolling and Back stay allowed).
STATUS: JS ISOLATED-TESTED with a fake phone that has AXON, Notes, Bank and Chrome apps (open, ambiguity, money-app question, typing question, step lists, resume, decline, stop, failures). Java compiled only against stand-in Android classes here; the cloud build is the real compile. Phone behaviour NOT RUN.
NOT BUILT (and why): the brain/chat wiring and any capability registration (tool-connection lane, D471; owner decides when); any screen (AI Studio, only when the owner and all Directors agree); app-specific knowledge (how a particular app works); icon caching; background-launch behaviour on a real phone (PHONE TEST item: Android restricts starting apps from the background, the accessibility service is the best route, unproven).
OWNER DECISIONS: (1) review SENSITIVE_PATTERNS; (2) default autonomy "navigate" (plain taps run without asking, risky ones ask).
BOUNDARIES: touches only files named here.
