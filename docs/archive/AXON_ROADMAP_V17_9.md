## 2. WHAT AXON IS FOR, AND HOW IT MUST FEEL
AXON is an Android app (Capacitor, React, TypeScript; built in Google AI Studio, kept in GitHub, built to an APK by GitHub Actions). It must be an intelligent, truthful, conversational assistant with an English dictionary as its understanding, plus tools and media. It reads what is said and what came before, finds several instructions in one message, answers each, notices mistakes, says plainly what it does not know, and never claims an ability it lacks. AXON uses explicit, testable parts and may add a model later as a second tier supervised by those checks. The real work is the language layer; the dictionary is its first ingredient.
**Who AXON serves (owner, 2026-10-22, binding):** AXON works for its owner. The owner comes first; its purpose is to get the owner the results asked for and make life easier, inside the Charter and the truth. To the OWNER it tells the complete truth, and the owner can always see the exact message sent to any outside AI or tool and what came back. The laws are the owner's alone: no law, rule or default enters AXON unless the owner has read and approved it; the Director only proposes.
**Design philosophy (owner, 2026-10-16, binding on every screen):** simple, clear, organised, professional; a page is understood at a glance (what it does, what the person can do, where to go next). Show the few main choices first; reveal the rest only when the person goes in. A pretty screen that is hard to read is a failed screen (an earlier AXON was scrapped for piling things on things). Every screen prompt says this and each screen is checked against it. **One look everywhere (2026-10-17):** the same header band on every screen (logo fixed left, "AXON" bold with the page name lighter beside it, small-caps line under); the back control is a slim row UNDER the band; lists are plain rows (36 px icon, name, chevron), no boxed cards; no per-row "Coming soon" badges (unbuilt items dimmed, one quiet line says so); the Tools home shows group names only; a header may fold away ONLY on editor screens. Source, Build and Interface Capture screens are locked. **Look:** keep the current identity (dark, calm, #ECECEC text, lucide icons, small-caps taglines, header band); no new colours, fonts or icon sets.

## 12. LESSONS AND FAILURE PREVENTION (full catalogue: `docs/DIRECTOR_HANDBOOK.md`; capacity rows: `docs/AI_CAPACITY.md`)
Real failures: tests that do not block the build let defects pass, so run them; acceptance numbers are derived, never remembered; measure before fixing; overloaded builders deliver nothing; a builder sent into a zip of documents reads them all and builds nothing (2026-10-24); a rule the builder's sandbox cannot satisfy makes it deliver nothing (2026-10-24); a third attempt after two failures breaks FL4; adding phrases is not intelligence (FL13); a screen needs the owner's phone; the Director sandbox type-checks only single files (offline mini-base config), so the cloud build is the real proof; a builder's own test can be wrong, so run it. **Prevention:** every prompt is sized from the capacity log, names its files (STOP if missing), says what to deliver if it cannot finish, and sets no demand the sandbox cannot meet; engine jobs only create files; screens never re-implement engines (FL14); never merge without `verify_return.py` and a report; update the board after every step.
