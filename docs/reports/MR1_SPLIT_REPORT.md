# MR1 report: the second, looser reading of a message (Director job, 2026-11-07)

WHAT IT DOES (plain words): when a message holds several requests ("define x and define y", "count words in "a b", also count lines"), the first reading sometimes keeps them as ONE piece and the later pieces are lost. MR1 adds a second, looser way to cut the same message. The second cut is only a candidate. It replaces the first cut ONLY when every piece of it is a sure tool match or a greeting/thanks, and at least one is a tool match. Otherwise the first reading stays, exactly as before.

FILES CHANGED: src/brain/mind/meaning/clauses.ts (startsClause and splitClauses take a `loose` flag, default false), src/brain/mind/meaning/build.ts (buildMeaning passes it), src/brain/mind/types.ts (MindContext.splitMeaning), src/brain/mind/stages.ts (meaning stage keeps the second reading as an alternative; resolution stage resolves both and applies the adoption gate; the route record inside the closure is named `routed` so the router-shadow rule "no file outside the router reads .routes" still holds).
