# AXON BRAIN DESIGN (moved out of the roadmap on 2026-10-20 so the roadmap keeps room; it BINDS exactly like the roadmap; read it before ANY brain job)

Section 7 of roadmap v16.7, unchanged except 7.10 (weakest phone tier). The mind system that wraps these stages is roadmap 7A and `docs/AXON_VISION.md`.

**7.1 Purpose.** AXON reads what is said and what came before, finds each instruction, answers each, notices mistakes, says plainly what it does not know, and never claims an ability it lacks. It is a reading, deciding and CHECKING machine made of explicit, testable stages, not one trained blob. **Honest limit:** with a dictionary and rules it understands a defined domain reliably and says when it does not; open conversation at a large trained model's level is not promised.
**7.2 Ten stages, each typed, pure, traced (every stage writes a trace entry, so "how did you understand me" is real data):** 1 Intake (utterance: text, place, time, id) [B1 done]; 2 Reading (language vs MATERIAL: code, quotes, pasted text are never interpreted; symbols) [B1]; 3 Analysis (tokens with positions, lemmas, parts of speech, word concepts through the knowledge slot, multi-word entries, per-message block budget and cache) [B2 done]; 4 Meaning (the Frame) [B3]; 5 Resolution (match the Frame to action schemas by concept distance) [B4]; 6 Dialogue (pending questions, follow-ups, "more", "it", "that", topic) [B5]; 7 Planning [B6]; 8 Execution (typed arguments through the kernel, never free text; legacy handlers until retired); 9 Verification [B6]; 10 Response (composed from the structured result in AXON's voice) [B7].
**7.3 Data the stages pass:** Utterance; Material region; Token (text, span, lemma, part of speech, concept ids); Clause; Frame {speech act: ask, command, teach, correct, greet, thanks, chat, unknown; predicate concept; slots; polarity; confidence; alternatives}; Slot {name, type, value, source span, confidence}; Candidate action {schema id, score, missing slots}; Plan {steps, order, dependencies, risk, permissions, questions}; Result {value, evidence label, source}; Trace {stage, input digest, output digest, ms}. Slot types: number, quantity with unit, date or time, text span, material region, file, choice, reference to an earlier turn.
**7.4 What the brain must KNOW (all behind the knowledge slot or the registry):** the core dictionary (never rewritten); the user dictionary UD1 (labelled "from your dictionary"); taught meanings and corrections (undoable, never silently overwritten); morphology; the small closed set of English function words (articles, pronouns, prepositions, conjunctions, auxiliaries, question words), which is grammar STRUCTURE and not vocabulary (FL13 allows it); entity knowledge (people and places, taught by hand first; the data has none); the live capability registry (what exists, works, is unbuilt); conversation state; user settings; clock and locale.
**7.5 Understanding mechanics.** Tokenise; lemmatise; tag parts of speech from the dictionary plus context rules; chunk phrases; split clauses (several instructions per message: attach material to the nearest earlier instruction lacking it; a second test set must NOT be split); detect the speech act from generic English structure (imperative starts with a verb, a question inverts or uses a question word, a teaching message says what something means); read negation, quantity, units; resolve "it", "that", "the last one" from state; tolerate typos by dictionary edit distance with a score penalty; read symbols as hints that raise or lower confidence, never as rules; treat code as untouchable material. A handler receives arguments, never the text. Ambiguity asks with choices. Confidence is a number with a recorded reason; RUN_AT 0.8, ASK_AT 0.5 (`src/brain/matcher.ts`); below ASK_AT AXON says it does not understand. Only exact and near word links may replace a word, each replacement lowers the score.
**7.6 Deciding.** Resolution scores synonym 1.0, then hypernym and hyponym decaying, plus act match and slot completeness. Planning orders instructions, asks for what is missing (with choices), asks before anything destructive or irreversible, checks permissions, keeps an undo copy before device file changes, and enforces budgets. Execution runs with timeouts and cancel; a failed stage is traced as failed, not as not-built.
**7.7 Checking (Verification, stage 9): why careful answers are careful.** Large assistants feel careful because of broad training, training that rewards admitting uncertainty, working through steps before answering, and tools used to check (search, calculation). The Director does not know any vendor's exact internals and AXON cannot copy the breadth; it CAN copy the behaviours as mechanisms: (1) COMPUTE, NEVER RECALL: numbers, dates, conversions and counts come from tested engines and are re-derived by a second independent path when cheap; (2) PROVENANCE: every claim in a reply carries its source (dictionary entry, tool result, taught by you, earlier in this chat); an unsourced claim is not stated as fact; (3) EVIDENCE LABELS: PROVEN (independently recomputed), CHECKED (verified against its source), REPORTED (taken from a source, not rechecked), UNSURE (said plainly); "found" is said only after checking; (4) ABSTAIN: "I do not know" and "I did not understand" are first-class results, never filled by a guess; (5) REQUEST-VERSUS-RESULT: compare what the Frame asked (unit, count, scope, order) with what the Result did before answering; (6) SELF-KNOWLEDGE only from the live registry; (7) honest failure messages from a fixed error taxonomy; (8) TRACE for audit; (9) a correction from the owner becomes a taught meaning, visible and undoable.
**7.8 Response and voice.** Compose from the structured result in this order: (a) answer or verdict, (b) evidence line if a check was made, (c) meaning and any risk, (d) next step, (e) fallback line. Calm, plain, thoughtful, progress first, no slang; firm once checked, plainly unsure otherwise. Wording variety comes from sentence structures, not from phrase lists used to understand.
**7.9 Memory and state.** Short-term: the turn history, pending question, topic, last results (bounded). Long-term: Z4 user data only, with size caps, export, erase, schema versions. Nothing leaves the phone unless the owner permits it per action.
**7.10 Budgets and safety.** Understanding must fit well under half a second on the WEAKEST supported phone tier (the owner's Infinix Note 10 is a test device, not the target; NOT measured: measure before B4, and per tier); lazy dictionary blocks, a per-message block budget, caches, cancel. Destructive actions confirmed; AXON Code runs only in a sandbox; no network without permission; secrets never in logs.
**7.11 Test strategy.** The GOLDEN TRANSCRIPT (`tests/fixtures/brainGolden.json`, 79 messages) is replayed after every stage: only changes the stage names may differ. B3 and B4 begin with a written corpus of positive AND negative messages (proof: confusion table). B5: scripted multi-turn transcripts. B6: transcripts and mutation tests (several instructions, risk questions, evidence labels). Also property tests, adversarial inputs, an "it says it does not know" suite, and a static test forbidding regular-expression literals inside `src/brain/mind`. `tests/capabilityTruth.test.ts` and `tests/engineTruth.test.ts` tie menu, registry and engines. Known weaknesses to fix in order: execution receives only raw text until B4; context fields are optional; the trace is discarded by `ask()`; pending-question state lives outside mind.
**7.12 Migration and later.** Strangler: B1 wrapped today's providers as LEGACY HANDLERS (`src/brain/mind/legacy.ts`, each with the stage that retires it: local rules and dictionary provider B4; taught meanings B5; foundation fallback B6). Order: B3 Meaning, B4 Resolution (typed arguments; tools run from chat; chat actions become available only when a test proves it), B5 Dialogue, B6 Planning and Verification, B7 Response composer, B8 memory and state. An optional model tier (never in the base app; download, checksum, space check) would only PROPOSE a Frame or Plan as typed JSON that the stages above verify; it is an owner decision after B6.
