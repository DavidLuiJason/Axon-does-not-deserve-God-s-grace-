## Self-testing code (the Claude-like habit) [wish]
- AXON builds complex code and tests it itself in a sandbox: runs it, attacks it with nasty cases, finds problems, fixes, and RE-RUNS every time. It never gives code it has not run.
- AXON can take code the owner gives it (for example from another AI), find problems, say what each problem was, and either offer the fix or give the fixed code, as the owner asks. It knows how to test and verify.
- Plan: part of AXON Code (AC2 to AC4) and the Mind system loop (M1: plan, act, check; success test written first). The method used by the Director (mutation tests) is the model.

## Frustration (needs the tone glue, built 2026-10-26) [wish]
- When AXON detects frustration it does a full plan and deep check from the foundation: what is failing, why the owner is probably frustrated, what the real fix is. No empty "I know you're frustrated". It may say it understands, say it thought it through, state the problem first, then give a solution, in flexible wording (the personality is not built yet).
- Director note: today a weak tone flag can fire by mistake ("he is sore"), so the deep dive must start only on strong signals or repeated trouble, and its first step is to check AXON's own last answer. Words inside quotes, "you are useless", "fed up", "sick of", "this frustrates me" are not read yet (known limits, to be fixed; the owner suspects more exist).

## Knowing its own limits [wish]
- AXON knows what it can and cannot do (tools, device). For a big job it splits the work into sections.
- It does not guess device limits: it says "I do not know my limits on this device; run tests?" and, if the owner agrees, runs several tests (speed, memory, heavy code), records the result, and either shows it or deletes the test work and keeps the numbers.

## Understanding people [wish]
- Filler words, grammar mistakes, human pauses. A word's type and tone when given a single word. Reverse engineering.

## Video, images, knowledge packs [wish]

- Must never lag the phone: packs sit in storage and are loaded only when needed, not kept in RAM. Needs a full plan before any work (size budget, loading, speed).

## 2026-10-30 (owner, dictated; Director verdicts per roadmap rule 12; PROPOSED, nothing built; each needs a design job and the owner's yes)
**R-U1 UNDERSTANDING REPAIR (the "decoder").** The owner wants AXON to break any incoming message (from the owner or from another AI tool) into a simplified meaning for the brain, notice what does not belong (repeats, restarts, a stray fragment between two parts that join, words it does not know, a message sent twice) and still understand, the way Claude read the owner's foggy dictation (repeated taps in the middle of a text and new recordings). DESIGN (Director): a new stage between 3 ANALYSIS and 4 MEANING; bounded cheap checks in a fixed order; unknown word: nearest dictionary words by spelling distance and by fit with its neighbours (the noisy-channel method of spelling correctors); repeated or restarted span: keep the last complete version; a message that repeats an earlier one is the same request, not a new question; each repair keeps the original, is labelled INFERRED (7F rule 7) and shows in the trace; no phrase lists (FL13). HOW THE BEST SYSTEMS DO IT: large trained models absorb this noise implicitly, which needs chips AXON does not have; smaller dictation systems use explicit steps: disfluency removal (repeats, restarts, fillers), spelling and speech-recognition correction by the noisy-channel method, and a dialogue policy that acts, confirms or asks by the expected cost of being wrong. AXON can copy the explicit steps; it cannot copy the implicit understanding. VERDICT: repeats, restarts, typos and unknown-word repair WORKS (common cases: good chance; on long spoken messages like the owner's: FAIR, because mixed-up order and half sentences are hard); scrambled or twisted wording CANNOT JUDGE; the optional model tier (7.12) is the honest tool for that rest.
**R-U2 ACT-OR-ASK BY COST.** Owner 2026-10-30: asking when unsure is better than guessing and failing, but asking on every simple task is annoying and annoyance grows into dislike; so understand more and ask less. DESIGN: decide by the COST of a wrong action (EFFECTS, UNDO and COST already exist in every schema), not by confidence alone: reversible and cheap: act and say what was understood ("I read this as X; tell me if not"); a close tie or one unknown word: show the best result AND ask "did you mean Y?"; irreversible, costly, sending, deleting or money: ask first and name the readings; never ask what the context already answers; one question at most; remember corrections so the same slip is not asked twice. This refines the 2026-10-28 decision (confirm, do not ask) by adding the cost test; owner to confirm. VERDICT: WORKS (the schema fields exist); the quality of the reading depends on R-U1 and on the concept gaps in the roadmap's GAP LEDGER.
**R-W15 DETECTIVE.** Observation, then ranked possible causes labelled INFERRED, then the cheapest check (example from the owner: a plan that cannot state its own prompt count hides gaps). Lives in Judgment (7C) and the Council GAPS seat. VERDICT: WORKS ONLY IF written as typed evidence rules per domain; open-world detective work CANNOT JUDGE.

VERDICT: WORKS ONLY IF limited to wording (tone) and patterns the owner consented to keep (style profiles, 7D); hidden feelings cannot be read; one short check, never theatre.
**R-W17 DEVICE MANAGER.** List background apps by recent use and memory and offer to close the unneeded ones for a heavy task, ask before closing, offer to reopen. VERDICT: WORKS DIFFERENTLY (HYPOTHESIS from general Android knowledge, not tested on the Infinix): an app can usually stop only other apps' background processes; real force-stop needs an Accessibility Service driving Settings or system rights; closed apps often restart and cost battery. Needs Usage Access permission; Charter ASK for every close; phone test first.
**R-W18 CIPHER AND CODED WRITING.** Writing that hides meaning with more or fewer words, numbers, symbols or stars. VERDICT: WORKS as exact engines with round-trip tests: standard encryption (AES-GCM through the phone's WebCrypto), classic ciphers, agreed coded writing; never invent new cryptography; no "unbreakable" claim; the owner's own text only.
**R-W19 SPEED.** Measure first on the owner's phone (job BM1, not done); then lazy loading, per-message cache, Web Worker, exact engines, spill to storage; the weakest phone tier decides.
**R-W20 INVERTED THINKING (owner 2026-10-31).** AXON must not think only of how it can succeed; it must also think how it could FAIL, because looking only at success blinds a mind to its own mistakes and miscalculations. VERDICT (Director): WORKS if built as a bounded, typed step (a pre-mortem), not as free-form self-doubt. Design direction: before an action with a cost, an effect or no undo, the plan lists a few concrete ways it could fail (wrong tool, wrong value taken from the message, stale state, a missing input, a result that looks right and is not) and each one gets a CHECK that runs and a result; a risk that cannot be checked becomes a question to the owner (Charter ASK) or a plain statement of the doubt. It sits with the success condition on every Frame (R1), the loop's success test (C31), and the Verification stage (B6); it reuses OPEN_ITEMS 36 (failure-chain map). Cheap and quick actions (a free, undoable tool) skip it, so AXON does not become slow or anxious. Evidence over feeling: a failure idea counts only when a check can show it. UNSIZED: needs a Director design (where the checks live, how many per action) before any prompt; first use is the execution contract (C1): confirm-before-run and verify-after-run.
